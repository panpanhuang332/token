Token:AI 的計費單位與思考單位

AI 不是一個字一個字讀,而是一塊一塊讀;那個「塊」就叫 token。你打的每句話會先被切成 token,AI 公司也照 token 的數量跟你收錢。先玩玩看👇

本工具使用 OpenAI 開源分詞器(tiktoken 的 o200k_base 編碼,GPT-4o / GPT-5 系列同款);Claude 與 Gemini 的分詞器不同,實際 token 數會有出入。空格與換行也是 token 的一部分(以 ␣ 和 ⏎ 顯示)。

看完這個網站,你就能跟同學解釋:token 是什麼、為什麼中文和英文切出來不一樣、AI 公司怎麼靠 token 收錢。

第 1 章CONCEPT

Token 到底是什麼

生活比喻

想像一列火車:整句話是「一整列火車」,字母或單一筆畫是「一顆顆螺絲」。AI 讀文字時,兩種都不用——它把句子拆成一節一節的「車廂」,有的車廂長、有的短。token 就是那些車廂。也可以想成樂高:同一面牆,你可以用 1×1 的小磚慢慢拼,也可以用現成的大塊零件快速拼;分詞器手上有一大盒「常見零件」,能用大塊就用大塊,拼不出來才退回小磚。

白話定義

token 是 AI 模型讀和寫文字的最小單位。它不等於「字」,也不等於「詞」,而是介於兩者之間、由統計決定的「常見碎片」:在訓練資料裡越常一起出現的字母(或位元組)組合,越有機會被合併成一個 token。

實際例子

英文單字 "unbelievable" 可能被切成 unbelievable 三塊(示意;各家分詞器切法不同)——注意這三塊都不是完整的「詞」,它們只是統計上常見的碎片。中文的「臺北市」依分詞器不同,可能是 1 個、2 個或 3 個 token。你可以現在就回到上面的即時分詞器輸入這兩個詞,看 o200k 實測結果。

一句進階補充

每個 token 在分詞器的「詞彙表(vocabulary)」裡都有一個固定編號,模型內部處理的其實是這些編號,而不是文字本身;現代分詞器的詞彙表大約有 10 萬~20 萬條。

第 2 章TOKENIZER

分詞器(tokenizer)怎麼切

生活比喻

想像你在幫全校訂便當,登記菜名時發現「排骨飯」被點了三千次。與其每次都寫「排、骨、飯」三個字,不如發明一個縮寫「🅿」代表整個詞——省時省紙。分詞器建詞彙表的過程就是這樣:把最常一起出現的組合,登記成一個新的「縮寫」,而且重複做幾十萬次。

白話定義

最主流的做法叫 BPE(Byte Pair Encoding,位元組對編碼):從最小單位「位元組(byte)」出發,統計哪兩個相鄰單位最常一起出現,把它們合併成一條新詞條,然後不斷重複,直到建出一本約 10 萬~20 萬條的詞彙表(vocabulary)。切句子時,分詞器會盡量用表裡「最大塊」的詞條去比對。

實際例子:BPE 逐步合併示意

假設訓練資料裡只有三個單字:hug、hugs、hugging。按「下一步」看詞彙表怎麼長出來。

一句進階補充

三大公司的分詞器各自不同:OpenAI 用開源的 tiktoken(現行編碼 o200k_base,約 20 萬詞條)、Google 用 SentencePiece 系列、Anthropic 的分詞器未公開——所以同一句話在三家切出來的 token 數不一樣,這件事第 6 章談錢的時候會變得很重要。

第 3 章核心章節

中文 vs 英文:誰比較「花 token」?

生活比喻

把 token 想成「行李箱格子」。英文像很多小件衣物,通常四件可以捲成一捲塞進一格;中文像厚毛衣,一件常常就要佔一格,遇到特別「蓬」的罕見字,甚至要拆開塞兩三格。同一趟旅行(同一個意思),兩種打包方式用掉的格子數不一樣——而 AI 公司是按格子數收錢的。

英文的經驗法則

白話定義

OpenAI 與 Google 的官方經驗法則(官方經驗法則,非精確值):1 token ≈ 4 個英文字元 ≈ 0.75 個英文單字;換句話說,100 tokens ≈ 75 個英文單字。像 "the"、"and" 這種超常見單字通常整個是 1 個 token,長字才會被拆開。

中文:一個字通常 1 個 token,但不一定

白話定義

電腦儲存文字用 UTF-8 編碼,裡面一個中文字 = 3 個位元組(bytes)。分詞器的詞彙表如果收錄了這個字,它就是 1 個 token;罕用字(例如「龘」「彧」)可能不在表裡,就會退回位元組層級,被拆成 2~3 個 token。平均來說,中文大約是 1~1.5 token/字,依分詞器而異——這是保守的粗略範圍,不是定律,最準的方法是用本頁工具實際測。

實際例子

用本站的 o200k 分詞器實測看看:「天」「氣」這類常用字幾乎都是 1 字 1 token;把「魑魅魍魎」貼進分詞器,你很可能會看到單一個字被拆成好幾塊(o200k 實測,結果依輸入而定)。同樣 20 個字的中文句子,token 數可能從 20 到 30 幾都有。

思辨題:中文字數少但每字 token 多;英文字母多但 4 個字元才 1 token——同一個意思,到底誰划算?

答案:視句子與分詞器而定,請實測,不要背結論。

兩股力量在拔河:中文字數少(「人工智慧」4 個字,英文要 "artificial intelligence" 23 個字元),但每個字的 token 效率較差;英文字元多,但分詞器對英文的壓縮特別好。哪邊贏,取決於句子用詞的常見程度、以及你用的是哪家的分詞器。與其背「中文比較貴」或「英文比較貴」,不如養成習慣:用下面的對照工具丟一組句子測測看。

語言稅(tokenization premium):一個真實的公平性議題

白話定義

分詞器的詞彙表是「投票」出來的,而訓練語料裡英文佔大宗,所以英文分到最多「大塊零件」。許多非英語語言(尤其資源較少的語言)表達同樣的內容要花更多 token——意思是:同樣的話更貴、也更快塞滿上下文窗口(context window)。這不是陰謀論,而是 AI 公平性領域真實的研究議題,有研究把它稱為「tokenization premium(語言稅)」。

一句進階補充

這也是各家不斷改版分詞器、擴大詞彙表的動機之一:詞條越多,非英語語言被拆碎的機率越低,但模型的輸出層也會變大,是工程上的取捨。

第 4 章CONTEXT WINDOW

上下文窗口(context window):模型的記憶桌面

生活比喻

寫報告時,你的書桌就這麼大:課本、講義、筆記全部得攤在桌上你才「看得到」;桌面滿了,要放新的就得把舊的收走。模型的「工作記憶桌面」就是上下文窗口——桌面上放的不是紙,是 token。

白話定義

上下文窗口(context window)是一次請求中,輸入+輸出合計能容納的 token 上限。超過就放不下:模型會拒絕、或「忘掉」前面的內容。為什麼要設上限?因為模型的注意力機制(attention)要讓每個 token 都去「看」其他 token,運算量隨長度快速成長——越長,越貴、越慢。

實際例子

目前三家旗艦的窗口(2026 年 7 月,詳見第 7 章價格表):OpenAI GPT-5.5 約 1M(100 萬)token、Anthropic Claude 現行主力多為 1M、Google Gemini 3.1 Pro 到 2M(現役最大)。1M token 大概是什麼概念?以官方經驗法則估算,約 75 萬個英文單字——差不多是《哈利波特》全套七集的量級(估算)。

一句進階補充

窗口以 token 計,不以「字」計——呼應第 3 章:同一個 1M 窗口,「塞得下幾個中文字」和「幾個英文單字」是兩個不同的數字,而且依分詞器而異。

第 5 章HOW IT THINKS

知識面:模型「用 token 思考」

生活比喻

模型像一個超強的「文字接龍玩家」:你給它前半句,它每次只做一件事——猜下一塊該接什麼,接上之後再猜下一塊,一路接完整個回答。

白話定義

每個 token 進入模型前,會先被轉成一長串數字(稱為 embedding,嵌入向量);模型讀完桌面上所有 token 後,只做一件事:預測下一個 token。所謂「生成一段話」,就是把這個動作重複幾百、幾千次。

實際例子:2025 年後的關鍵新知——思考 token

新一代的「推理模型(reasoning model)」在給你答案之前,會先在內部「打草稿」:自己跟自己推演、驗算、否決錯誤路線。這些草稿也是一個一個 token 生成的,叫做推理/思考 token(reasoning tokens)。重點來了:草稿你看不到,但照樣按「輸出 token」的價格計費。一題數學的答案可能只有 200 字,背後卻燒掉了幾千個思考 token——第 6 章會把這筆帳實際算給你看。

一句進階補充

「預測下一個 token」聽起來簡單,但為了預測得準,模型必須在內部學會文法、常識、甚至推理——這就是大型語言模型(LLM)能力的來源。

第 6 章ECONOMICS

經濟面:token 就是錢

生活比喻

API 的計費像「按秒計費的國際電話」,只是單位不是秒,是 token。你講的每一塊、AI 回的每一塊,甚至 AI 心裡默念的每一塊,都在跳表。以下 8 個機制,每個都配一個小例子。

  1. 輸入(input)與輸出(output)分開計價,輸出貴 4~6 倍。 「讀你的話」便宜,「生出新的話」貴——因為生成每個 token 都要把整個模型跑一輪。倍數(2026-07 官方定價):OpenAI 旗艦 GPT-5.5 約 6×($5 → $30)、Anthropic 全線 5×(如 Fable 5:$10 → $50)、Gemini 3.1 Pro 約 6×($2 → $12)。
    小例子:同樣 1,000 個 token,用 GPT-5.5 當輸入只要 $0.005,當輸出要 $0.03——差 6 倍。
  2. 看不見也要錢:思考 token 以「輸出價」計費。
    小例子:一題數學,答案 200 字(約 300 token,估算),但模型內部打草稿用了 3,000 個思考 token。用 Claude Fable 5(輸出 $50/MTok)算:(3,000+300)×$50÷1,000,000 ≈ $0.165,約台幣 5.1 元(以 1 USD = 31 TWD 估算)——其中九成的錢花在你看不到的草稿上。
  3. 提示快取(prompt caching):重複的開頭,約 1 折。 很多請求的開頭都一樣(例如同一份系統提示)。服務商把這段「背起來」,下次再讀就便宜:讀取價約為原價 1 折。
    小例子:一份 10,000 token 的系統提示,GPT-5.5 原價每次 $0.05,快取命中後每次約 $0.005(快取輸入 $0.50/MTok)。
  4. 批次處理(Batch API):不趕時間,打 5 折。 願意等(通常 24 小時內完成)的工作,OpenAI、Anthropic、Google 三家都5 折。
    小例子:要幫 1,000 篇文章做摘要,又不急著今天拿到?走 Batch,帳單直接砍半。
  5. 長上下文加價門檻:塞太多,單價變貴。 Gemini 3.1 Pro 超過 20 萬 token 後,輸入變 2 倍($2→$4)、輸出 1.5 倍($12→$18);OpenAI GPT-5.5 / 5.4 超過約 27 萬 token 也有加價費率;Claude 現行 1M 窗口機種全程同價、無加價。
    小例子:第 8 章的試算機選 Gemini 3.1 Pro、輸入打 250,000,會看到費率自動跳高。
  6. 標價 ≠ 有效成本:分詞器不同,token 數就不同。 兩家單價一樣,不代表同一段文字花一樣的錢——因為各家切出來的 token 數不一樣。實例:Anthropic 自 Opus 4.7 起(含 Sonnet 5、Fable 5)換用新分詞器,同樣文字的 token 數可能比舊款多出最多約 35%——單價沒變,帳單卻可能變貴。
    小例子:同一份 100 萬 token(舊分詞器計)的文件,若新分詞器切成 135 萬 token,即使單價相同,輸入費用也多 35%。
  7. 訂閱制 ≠ API:兩種不同的商品。 ChatGPT Plus、Claude Pro、Google AI Pro 是「月費吃到飽(有額度)」的聊天產品;API 才是「按 token 計費」的開發者服務。名字常被混用:ChatGPT 是產品名,API 上的模型叫 GPT-5.5;Claude、Gemini 同理。
    小例子:訂了 ChatGPT Plus(US$20/月)不代表你能用 API 寫程式呼叫 GPT-5.5——那要另外按 token 付費。
  8. 工具定義、系統提示、對話歷史,全都算輸入 token——聊越久,每一句都越貴。 每次你送出新訊息,整段對話歷史都會重新當成輸入再算一次錢。
    小例子:聊到第 50 句時,前面 49 句(可能好幾萬 token)每次都要重新計費——這正是「提示快取」存在的理由。
一句進階補充

有感換算:一篇 500 字的中文作文約 700 token(估算,以 1.4 token/字計)。拿去給 Claude Sonnet 5 讀(輸入 $2/MTok),成本約 $0.0014,約台幣 0.04 元;請它「寫」一篇同樣長度(輸出 $10/MTok)約 $0.007,約台幣 0.22 元(以 1 USD = 31 TWD 估算)。單次很便宜——但乘上百萬使用者,就是 AI 公司的整條營收。

第 10 章GLOSSARY

詞彙表 + 資料來源

tokentoken
AI 讀寫文字的最小單位;由統計決定的「常見碎片」,介於字與詞之間。
分詞器tokenizer
把文字切成 token(並轉成編號)的程式;各家不同,同句話切出的數量也不同。
位元組對編碼BPE, Byte Pair Encoding
建詞彙表的演算法:反覆把「最常相鄰出現」的組合合併成新詞條。
詞彙表vocabulary
分詞器認得的所有 token 清單,現代約 10 萬~20 萬條,每條有固定編號。
上下文窗口context window
一次請求中,輸入+輸出合計能容納的 token 上限;模型的「工作記憶桌面」。
輸入/輸出 tokeninput / output tokens
你送給模型的算輸入,模型生成的算輸出;兩者分開計價,輸出貴 4~6 倍。
推理/思考 tokenreasoning tokens
推理模型回答前在內部「打草稿」用掉的 token;你看不到,但以輸出價計費。
提示快取prompt caching
把重複出現的提示開頭暫存起來,再次讀取時輸入價約打 1 折。
批次處理batch
不趕時間的請求集中處理,三家都打 5 折。
MTokmillion tokens
「每 100 萬 token」,API 報價的標準單位,例如 $5/MTok。
